# Phase 3 QuDDPM / Conditional QuDDPM Functional Validation

## Scope

This phase validates that the diffusion mechanics work before exposing the model to TFIM data. It deliberately uses synthetic one-qubit pole clusters and loads no TFIM train, validation, or test artifact. It is not an augmentation result.

The implementation is independent because the official QuDDPM repository has no source license and its current phase notebook is not directly reproducible. The mathematical design follows Zhang et al. (2024) and the conditioning mechanism follows Quinn et al. (2026).

## Model definition

### Forward process

Each target pure-state ensemble is progressively scrambled by independently sampled SU(2) rotations. The rotation scale increases with diffusion step. Validation requires the terminal ensemble to be closer to a Haar reference under fidelity-kernel MMD than the original structured ensemble.

### Reverse process

Each reverse step:

1. draws a one-qubit Haar source state;
2. prepares one ancilla with a class-conditioning angle;
3. applies a shared ancilla-data unitary with local `RX/RY`, fixed `CZ`, and trainable `XX/YY/ZZ` interactions;
4. samples and records the ancilla projective-measurement branch;
5. normalizes the remaining data state.

The trainable Pauli interactions make the two-qubit ansatz expressive enough to realize SWAP/amplitude-damping-like denoising behavior while preserving the paper's ancilla-measurement construction.

### Conditioning

Parameters are shared across classes. Only ancilla preparation changes:

- class 0: `μ = 0`;
- class 1: `μ = π`.

The conditional loss is the mean class-wise fidelity-kernel MMD. Reverse steps are trained from `T→0` with SPSA and fixed explicit random streams. Initialization, SPSA, forward, source, measurement, and generation seeds are separate.

### Loss

For pure-state ensembles `A` and `B`, the fidelity kernel is

`k(ψ,φ) = |⟨ψ|φ⟩|²`.

The smoke implementation minimizes biased MMD²:

`mean k(A,A) + mean k(B,B) - 2 mean k(A,B)`.

Wasserstein evaluation is deferred; it is unnecessary to establish basic forward/reverse/conditioning functionality.

## Configuration

`configs/quddpm/phase3_smoke.yaml` defines:

- 48 target states/class;
- 2 diffusion steps;
- 3 reverse-circuit layers;
- 800 unconditional or 1000 conditional SPSA iterations per reverse step;
- 128 generated states/class;
- physical tolerance `1e-10`.

Run:

```bash
uv run run-quddpm-smoke \
  --config configs/quddpm/phase3_smoke.yaml \
  --output results/quddpm_phase3_smoke
```

Artifacts:

```text
results/quddpm_phase3_smoke/
├── config.yaml
├── summary.json
├── unconditional/
│   ├── checkpoint.npz
│   ├── generated_states.npz
│   ├── history.json
│   └── metrics.json
└── conditional/
    └── ...
```

Generation is repeated from the serialized checkpoint—not the in-memory result—to test checkpoint reproducibility.

## Preregistered functional checks

- reverse two-qubit circuit is unitary;
- projective reverse output remains normalized and pure;
- forward process approaches Haar under MMD;
- every reverse-step training loss decreases;
- generated-target MMD is lower than Haar-target MMD;
- fixed checkpoint and seeds reproduce generated bytes;
- conditional class 0 has positive mean Bloch `Z`;
- conditional class 1 has negative mean Bloch `Z`;
- class parameters are shared and condition angles differ.

No arbitrary accuracy threshold is used. Strict directional improvement, physical tolerance, and reproducibility are the smoke gates.

## Interpretation boundaries

Passing this validation shows that the independently implemented forward scrambling, measured reverse map, stepwise optimization, checkpointing, and class conditioning are operational on a controlled one-qubit task. It does **not** show:

- successful 4-qubit TFIM distribution learning;
- adequate diversity for augmentation;
- improvement of QCNN performance;
- equivalence to unreleased conditional source code;
- QPU feasibility or quantum advantage.

The next Phase 3 gate is train-only 4-qubit TFIM conditional generation with explicit memorization, diversity, class-observable, and validation-only diagnostics. Phase 4 QCNN augmentation remains blocked until that gate passes.
